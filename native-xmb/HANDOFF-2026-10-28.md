## 2. What ships

What a user gets from this tree, with the limits kept in view. Items added since the 2026-10-27 handoff
are marked with the commit that landed them.

- **One Windows x64 executable**, `re-ps3-native.exe`, plus the Qt runtime `windeployqt` copies beside
  it. The build also produces the `xmb-reference-frames` helper and, with `-SteamworksHeaders`,
  `xmb-steam-client.exe`. No installer; the output folder is portable apart from the firmware it reads.
- **Rendering**: firmware-ported background/HDR/glare, ribbon cloth and FFD sheet, the 4.93 cold-boot
  intro, both particle passes, FreeType glyphs at the traced load flags with sub-pixel phase and a
  coverage-union mask, and category/item icons through the firmware glass material at full brightness
  (`23980a5`; opaque material only for dimmed states). Since `9545047` the particle spot direction, the
  depth-of-field band, the ICONS clock keyframes and the LINE1 schedule are **read from the MNU data at
  runtime** rather than fitted, and every remaining scene constant is annotated `fit` / `captured` /
  `fallback` / `derived`. The text shadow offsets stay contradicted and unchanged (`RCO-OBJECT-MODEL` 9.4).
- **Text**: `elideToWidth` with a separate firmware-shape ellipsis and caret metrics from the renderer's
  own advance (`23980a5`). Advances still come from Qt shaping - agreement with PAF within 0.11 px, not
  authority.
- **Menus**: the ten category columns, pages, information pages, the on-screen keyboard (including
  masked password input), the item-level Triangle options menu, the PS system menu, notifications, the
  volume HUD, Download Management and the in-XMB Jellyfin sign-in page. The Network column is generated
  from the firmware's XMBML; the other columns are still hand-built. Since `e171263`/`6cf54a4` the
  message surfaces are split by kind (inline line, titled page, box, error-code page, information page)
  and drawn from measured geometry and RCO colours and strings, with the invented 53% dim and the
  invented "OK" hint gone.
- **Messages**: a five-kind `MessageKind` model in the shell, the plate/bars/hint row drawn from the
  RCO values with PAF fades (200/1000/100/150 units), measured page geometry, both flat rules, the
  `page_btnnavi` glyph row with `msg_*` labels, two-button boxes and the confirm cue from the box's own
  path. The dialogs audit's own status table has all fourteen items done (`audit/DIALOGS-FIRMWARE.md`
  7.4). What remains is the modal box's own geometry (no firmware frame exists, so its rect, title
  position and hint baseline are native fits) and an error-code page in the shipped capture set (it is
  rendered, but the recipe needs a DOWN move and this machine's pad currently emits a constant up).
- **Session and power** (`067d6f0`): Auto-Off darkens the display instead of quitting (broadcast
  `SC_MONITORPOWER`, read back `GUID_CONSOLE_DISPLAY_STATE`, reversible), `--kiosk` / `--display` /
  `--start-windowed` with verified frameless fullscreen on a chosen display, real DualSense/DS4 battery
  and transport parsing in `pad.*` (hardware-verified 100% over USB), and `pause=` / F10 script tokens.
- **Services**: Steam library/collections/store/downloads/accounts/friends (`b339422` adds the two-step
  account-switch prompt with a dry run, `+app_stop` with a registry read-back, a friends avatar cache
  and the trophy verdict), native Jellyfin browsing and playback with DPAPI remembered sign-in and
  playback reporting (`3e5bcdf`), local photos, music and video with sidecar subtitles, resume points
  and the Video column's Continue Watching row, and the versioned imported-apps registry and editor.
- **Settings and state**: versioned `preferences.json` (document version 2, per-profile values and a
  v1->v2 migration in `Preferences`), `profiles.json`, theme files (`.p3t`) read in memory, host-backed
  volume/mute/display settings. The settings **pages** are still the old hand-built ones: the firmware's
  two page classes are specified in `audit/SETTINGS-FIRMWARE.md`, not implemented (Phase 11).
- **What does not ship**: firmware assets (a local `dev_flash` is required and never committed), build
  outputs, reference captures, Steam artwork caches, credentials, or any diagnostic bundle.

## 3. Build, run, verify

Unchanged from [HANDOFF-2026-10-27.md](HANDOFF-2026-10-27.md) sections 3 and 11; that file is still the
one-page operational reference. The short form, from the repository root:

```powershell
# Build. Stop re-ps3-native.exe first: the linker fails with LNK1104 while it runs.
& .\native-xmb\build.ps1
# -> out\native-xmb\re-ps3-native.exe plus the deployed Qt runtime

# Run. --dev-flash is required; without it the app prints usage and exits with code 2.
& .\run-native-xmb.ps1 -FlashRoot C:\path\to\dev_flash
```

Verification is the maintained product harness plus, for the fidelity track, the new parity tool:

```powershell
# Product gate: stored pair + canonical capture + named states.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\ab-layers.ts --all

# Fidelity corpus: catalogue, capture, score, references that are owed.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --catalogue
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --capture --score
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --references-missing
```

`work/release-check.ps1` wraps the release checks (gate, key scan, firmware/data scan, doc links). It
does not yet run `parity.ts --regression`; wiring that is Phase 16.3.

## 4. The gate families, and what they say today

Four instruments exist. Only the first three are one command; the fourth is the fidelity track. The
numbers are the **last recorded runs**, not measurements made for this file.

1. **Stored per-layer pair** (product gate, family 1): six named crops of the stored native root frame
   against the stored RPCS3 root frame (`out/native-reference/ab-native-root.png` vs `ab-rpcs3-root.png`),
   each gated at baseline minus 0.5 dB PSNR / 0.004 SSIM. Deterministic offline scoring. Last recorded:
   **6/6 PASS** - 18.20/0.8388 frame, 19.02/0.9251 top background, 20.13/0.9022 icon row,
   11.86/0.3791 item label, 10.33/0.3504 clock, 13.40/0.4973 info bar. These are historical comparison
   numbers, not a fidelity claim, and they cannot change without the reference files changing.
2. **Canonical capture** (product gate, family 2): the same six crops on a fresh native frame with every
   clock pinned (`--render-clock 30`, `--background-clock 2026-10-25T10:00:00`,
   `--ui-clock 2026-10-25T12:32:00`, `--focus-time 2000`). Last recorded green run (2026-10-27 19:25
   build, `out/native-phase3`): **6/6 PASS** - 18.28/0.8285 frame, 20.22/0.9336 background,
   20.89/0.8939 icon row, 11.94/0.3909 item label, 11.39/0.4105 clock, 14.78/0.6117 info bar. The
   committed thresholds still name `C:/dev/out/native-folders` as `capture.exe`, so a plain `--all` on
   the committed configuration is **red for a configuration reason** (it scores the 2026-10-26 build
   against references saved from the 19:25 build); that is Phase 8.3.
3. **Named states** (product gate, family 3): per-state dump assertions plus whole-frame and content
   crops at PSNR >= 55 dB / SSIM >= 0.9995 against a stored **native** self-baseline. Four states at
   HEAD (`steam-game-root`, `steam-all-games`, `steam-store-sections`, `steam-not-installed`); the
   in-flight harness adds nine (notification, volume HUD, options panel, Continue Watching populated
   and empty, dialog, subtitle cue, Jellyfin sign-in, download page) for **13 total, with no gate run
   recorded on that state** (PHASES-2026-10-28 0.1, 8.1). The dialogs pass deliberately invalidated one
   stored reference: `continue-watching-empty` now draws the inline line instead of the old dimmed
   modal, so its two pixel regions fail until tooling re-saves the reference (`6cf54a4`; that is a
   reference refresh, not a regression).
4. **Fidelity scorecard** (`work/parity.ts`, P0): 25 capturable states x 3 tiers. First end-to-end run
   (`scorecard-20261027-212148`): **0/25 states pass all three tiers; Tier A 22/25, Tier B 0/25, Tier C
   9/25, 4 cell gate failures.** One of 25 canonical cells has a reference at all, and it is the
   pre-contract root frame whose content differs by construction (Corrupted Data and the pre-Steam
   column; DD/MM 24-hour clock against the app's MM/DD 12-hour default). Tier B is therefore **not a
   measurement yet**; everything measured this week is unscoreable until Phase 9 fills cells.

What the gates cannot cover, unchanged: audio and cue timing, controller hardware, input repeat, live
Steam store/friends content, Jellyfin playback and network behaviour, window lifecycle, pointer input,
and human-length sessions. The ten-minute scripted stability run (WorkingSet 284 -> 230 MB, 190-234 fps,
no crash) remains partial ISC-29 evidence, not a gate.
