## 3. Build, run, verify

Unchanged from [HANDOFF-2026-10-27.md](HANDOFF-2026-10-27.md) sections 3 and 11; that file is still the
one-page operational reference. The short form, from the repository root:

```powershell
# Build. Stop re-ps3-native.exe first: the linker fails with LNK1104 while it runs.
& .\native-xmb\build.ps1
# -> out\native-xmb\re-ps3-native.exe plus the deployed Qt runtime

# Run. --dev-flash is required; without it the app prints usage and exits with code 2.
& .\run-native-xmb.ps1 -FlashRoot C:\path\to\dev_flash
```

Verification is the maintained product harness plus, for the fidelity track, the new parity tool:

```powershell
# Product gate: stored pair + canonical capture + named states.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\ab-layers.ts --all

# Fidelity corpus: catalogue, capture, score, references that are owed.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --catalogue
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --capture --score
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --references-missing
```

`work/release-check.ps1` wraps the release checks: it runs the layer gate as a **gate** (a non-zero
`ab-layers.ts --all` exit fails the run), `parity.ts --references-missing` as a **report** (it exits 1
while cells are missing; that number is published, never gated), and the credential, firmware-data,
dump, documentation-link and stale-commit scans. `-SkipBuild` is report mode (skips the two checks that
need a local build) and `-WhatIf` prints the plan without running anything. It does not yet run
`parity.ts --regression`; wiring that is Phase 16.3. Section 8 is the three-command shipping sequence.

### 4.1 The baselines correction of 2026-10-28

One number set in this file was wrong, and the way it was wrong matters more than the number.

the DD/MM reference frame, so the numbers improved for the wrong reason: the clock region held 302
bright pixels on that build against 1,677 on a text-bearing one.

`b0defd8` reverted the four text files, re-measured on a text-bearing build (frame 18.29/0.8342, clock
11.39/0.4500, info bar 14.98/0.7639) and **withdrew the startup slice's 147 ms first-frame gain** until
it can be re-landed with glyph output proven. `d1e45a8` added the guard that makes the failure
impossible to repeat silently: a capture must show at least 900 bright pixels in the clock crop before

### 4.3 What the gates cannot say, honestly

- **Audio is not gated.** No gate scores a cue, a level, a mix or a latency; the evidence is one trace
  line per decision plus the audits. A cue that fires at the wrong volume or the wrong moment would pass
  every gate in this file unchanged.
- **Tier B does not pass, and two of its cells are not even failures.** 0 of the 25 measured cells is
  inside every budget, 2 are informative (annotated content differences whose frames pass), and 23 gate.
  The losses are the band text rows, the row/list regions and the background. **No state is 1:1.**
- **Ten captured cells have no reference.** Five are firmware states (`column-tv`,
  `page-download-management`, `notification`, `volume-hud`, `media-player-panel`) and five are
  native-only pages that owe none. `media-player-panel` is proven unattainable on this rig - the
  console's media columns come from the MMS metadata database, not a directory scan (`61d4e8c`).
- **The budget policy is unchanged.** The three class budgets and the two region overrides are still the
  2026-10-27 provisional numbers, and scorecard 18 records that no budget was changed to move a cell.
  Phase 9.5 is where they get calibrated against matched references.
- **The named-state family needs one recorded run.** Its references are self-baselines, not firmware
  equality, and they were re-saved after the waves (4, family 3). A re-save is not a pass until the run
  is recorded.
- **The month term is still a fit, and the parity corpus still uses the old date.** The canonical pin is
  corrected, but `backgroundTime()` still carries the documented time-of-day fit: the captured
  day-quantised constant renders the wrong palette at the pin and fails the gate (`8ef9ecd`), so the
  phase convention between the captured constant and the shader parameter remains unproven. And the

## 8. How to ship

Three commands, in this order, from the repository root. All three are local: none pushes, tags,
uploads or deletes anything.

```powershell
# 1. Build. Stop re-ps3-native.exe first: the linker fails with LNK1104 while it runs.
& .\native-xmb\build.ps1
# -> out\native-xmb\re-ps3-native.exe, the deployed Qt runtime, re-ps3-native.pdb

# 2. Gate. Product harness: stored pair + canonical capture + every named state.
#    Exits non-zero on a layer or named-state failure. This is the number a release quotes.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\ab-layers.ts --all

# 3. Release check. Runs the same gate (as a gate) plus the credential, firmware-data, dump,
#    documentation-link and stale-commit scans. Exits non-zero on any of them.
& .\work\release-check.ps1
```

What each command may be used to claim:

| Command | Claim it supports | What it cannot say |
|---|---|---|
| `build.ps1` | A build from this checkout produced `re-ps3-native.exe` and a complete Qt deployment. | Nothing about fidelity, and nothing about a clean clone until a `git archive` + build is recorded. |
| `ab-layers.ts --all` | 6/6 layer crops inside their budgets and 12/12 named states pass on the build the thresholds file names. | Only what its references are: the stored pair is a historical RPCS3 comparison, and the named states are native self-baselines, not firmware equality. On the committed configuration it also runs the stale `native-phase3` exe, and the named-state references are fresh only after a recorded run (section 4, family 3). |
| `parity.ts --references-missing` | How many captured cells still have no matched RPCS3 reference (10 of the 35 captured cells on 2026-10-28, 5 of them firmware-referenced states; the five native-only states owe none). | A fidelity score. Tier B is 0 pass / 2 informative / 23 gating with 25 measured; the command exits 1 while cells are missing, which is why release-check treats it as a report. |
| `release-check.ps1` | The tree carries no credential, no firmware-derived data, no committed analysis dump, no dead documentation link and no cited commit that does not exist - and, in a full run, that the gate passed. | Anything about rendering. `-SkipBuild` skips the gate, so a `-SkipBuild` PASS is not a release PASS. |

**What must be true before a tag.** This is Phase 8's exit criteria (PHASES section 2) plus the
operations rules; every line is checkable, not a judgement.

- [ ] `git status --short` is empty at the release commit, and the only files in it are the intended
      ones - another session's in-flight `view.cpp`/`shell.cpp` work is not swept in.
- [ ] A clean export of the release commit configures and builds with 0 errors and produces
      `re-ps3-native.exe` (the `git archive` + `build.ps1` run that is still owed; section 1).
- [ ] `bun work/ab-layers.ts --all` exits 0 **on the committed configuration**: 6/6 layers and 12/12
      named states, with its machine-readable report (`--json`) recorded in the tag notes or the release
      record.
- [ ] `work/release-check.ps1` exits 0 with `gate PASS`, not `gate SKIP`. A `-SkipBuild` run is a report,
      not a release gate.
- [ ] `work/release-check.ps1` prints `keys PASS`, `data PASS`, `dump PASS`, `docs PASS`, `stale PASS`.
- [ ] The version string agrees in `native-xmb/CMakeLists.txt` and `src/main.cpp`, and `--version`
      prints it.
- [ ] [ISA.md](ISA.md) states its checked count and every ticked criterion has a cited run in the same
      file (31 of 66 on 2026-10-28).
- [ ] [INSTALL.md](INSTALL.md) matches the CLI: every option in `src/main.cpp` is documented, and no
      documented option is absent from the code.
- [ ] Pushing and tagging are approved. Neither happens as part of a documentation or verification pass.

## 9. Release and tag checklist

**No tag exists today** (`git tag` is empty) and **this pass did not create one**: tagging is the
parent's decision. What follows is the exact procedure so the release is mechanical when it is approved.

### 9.1 Version string

- One version, two places, and they must agree:
  - `project(RePS3Native VERSION 0.2.0)` in `native-xmb/CMakeLists.txt`
  - `app.setApplicationVersion("0.2.0")` in `src/main.cpp`
- Today's version is **0.2.0**. `--version` prints `re-ps3-native 0.2.0`.
- The tag is `native-xmb-v<version>`, so today that would be **`native-xmb-v0.2.0`**.
- [PHASES-2026-10-28.md](PHASES-2026-10-28.md) 8.5 expects the release after the Phase 8 repair to be
  **`native-xmb-v0.2.1`**. A bump is a source edit to the two lines above (a two-file commit of its own,
  before the tag), not a tag-time decision.

### 9.2 Tag command and annotation format

Annotated tag on the release commit, never a lightweight tag:

```powershell
git tag -a native-xmb-v0.2.0 -F .\release-notes.txt <release-commit>
git show native-xmb-v0.2.0 --stat        # read it back before anyone pushes
git push origin native-xmb-v0.2.0        # only with explicit approval
```

`release-notes.txt` is ASCII and follows this shape - measured numbers, each with the command that
produced it, and no claim the gate cannot support:

```text
native-xmb v0.2.0

commit <40-hex release commit>
built with Qt 6.12.0 / MSVC 14.4x on Windows x64

gate    bun work/ab-layers.ts --all -> exit 0; 6/6 layers, 12/12 named states
check   work/release-check.ps1 -> RESULT PASS (6 passed, 0 failed, 1 report-only)
isa     31/66 criteria checked (ISA.md)
fidelity parity.ts --references-missing -> 10 captured cells without a matched reference (report only)
notes   <one paragraph: what changed since the previous tag; for the first tag, since a445f4a>
limits  <the two or three limits a user will hit first, taken from section 2, not paraphrased>
```

### 9.3 Commit message format

The repository's own style, unchanged: one subject line naming the phase or area and the change, then
optional body paragraphs with the measured numbers and the documents that carry them. No trailers, no
generated text, no emoji, no ALL-CAPS.

```text
Phase 8.5 packaging: INSTALL refreshed against the CLI, release-check extended, handoff ship list

<what changed, in the order a reader needs it; every metric with the command that produced it;
 the documents and audits that hold the evidence; what was NOT run>
```

A commit that quotes a status names the commit it was read at. A commit that changes a threshold, a
budget or a reference says so in the subject, because that is the change a reviewer must not skim.

### 9.4 What a release must not include

- **No tag on a red or skipped gate.** A tag is created only after a full `release-check.ps1` run with
  `gate PASS` on the tagged commit, and `ab-layers.ts --all` exiting 0.
- **No firmware assets or derived data** in any commit: no `dev_flash` tree, decrypted `*.prx`,
  `.rco`/`.prf`/`.gim`/`.p3t`/`.raf` containers, RCO/PRF dumps, shader dumps or contact sheets.
- **No Steam key, Jellyfin token, password, JWT, NPSSO or PSN id** in the tree, the notes, the commit
  messages or the tag annotation.
- **No captured frames, reference frames, named-state seed data or scorecards** in git; they are local,
  gitignored evidence (`out/`), and the release notes cite them instead of carrying them.
- **No build outputs** (`out/`, `*.exe`, `*.obj`, `*.pdb`) in the tree. The portable folder is a copy
  of the output folder, not a commit.
- **No version bump without the gate re-run.** If `CMakeLists.txt`/`main.cpp` change the version, the
  build and gate must be re-run before the tag, because the tagged binary is the one users get.
