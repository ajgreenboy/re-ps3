## 2. What ships

What a user gets from this tree, with the limits kept in view. Items added since the 2026-10-27 handoff
are marked with the commit that landed them.

- **One Windows x64 executable**, `re-ps3-native.exe`, plus the Qt runtime `windeployqt` copies beside
  it. The build also produces the `xmb-reference-frames` helper and, with `-SteamworksHeaders`,
  `xmb-steam-client.exe`. No installer; the output folder is portable apart from the firmware it reads.
- **Rendering**: firmware-ported background/HDR/glare, ribbon cloth and FFD sheet, the 4.93 cold-boot
  intro, both particle passes, FreeType glyphs at the traced load flags with sub-pixel phase and a
  coverage-union mask, and category/item icons through the firmware glass material at full brightness
  (`23980a5`; opaque material only for dimmed states). Since `9545047` the particle spot direction, the
  depth-of-field band, the ICONS clock keyframes and the LINE1 schedule are **read from the MNU data at
  runtime** rather than fitted, and every remaining scene constant is annotated `fit` / `captured` /
  `fallback` / `derived`. Decode is complete: 3,174 of 3,174 named images across 89 RCO containers
  (including the 224 palette-less masks and all 52 OSK textures) now decode with zero failures
  (`4c4b25e`, `e90b196`; `audit/TEXTURE-COVERAGE.md`). The remaining rendering gap is draw-side, not
  decode-side: five substitutions are named in TEXTURE-COVERAGE 4 (the information-panel plate, the
  indicator row, the OSK arrow-key masks, the `bestImage` `tex_music` swap and the Settings row icons),
  and none is applied.
- **Text**: `elideToWidth` with a separate firmware-shape ellipsis and caret metrics from the renderer's
  own advance (`23980a5`). Since `a445f4a` the shadow is the firmware's own `Text` material (offset
  4/-5, RGB .25, alpha 1, proven equal to `xmb_plugin_normal/clock` at runtime) multiplied over the
  layer with a labelled fit exponent; the old invented 0/0 at 0.2 is gone. Advances still come from Qt
  shaping - agreement with PAF within 0.11 px, not authority. The `view.cpp` class-name hunks that
  choose the material per label are recorded in TEXT-RENDERER 10, not applied.
- **Menus**: the ten category columns, pages, information pages, the on-screen keyboard (including
  masked password input), the item-level Triangle options menu, the PS system menu, notifications, the
  volume HUD, Download Management and the in-XMB Jellyfin sign-in page. The Network column is generated
  from the firmware's XMBML; the other columns are still hand-built, except that **Settings is now
  firmware-resolved**: 16 rows in firmware order from `category_sysconf.xml`, three real segment pages
  (Game 6, Accessory 14, Network 5) and corrected one-level page rows, each with a
  `settings-<page>.json` dump (`937babe`, `4c4b25e`). The OSK layout is read from its RCO and module
  (`68134a6`), but the OSK draw is still free-hand. Since `e171263`/`6cf54a4` the message surfaces are
  split by kind (inline line, titled page, box, error-code page, information page)
  and drawn from measured geometry and RCO colours and strings, with the invented 53% dim and the
  invented "OK" hint gone.
- **Messages**: a five-kind `MessageKind` model in the shell, the plate/bars/hint row drawn from the
  RCO values with PAF fades (200/1000/100/150 units), measured page geometry, both flat rules, the
  `page_btnnavi` glyph row with `msg_*` labels, two-button boxes and the confirm cue from the box's own
  path. The dialogs audit's own status table has all fourteen items done (`audit/DIALOGS-FIRMWARE.md`
  7.4). What remains is the modal box's own geometry (no firmware frame exists, so its rect, title
  position and hint baseline are native fits) and an error-code page in the shipped capture set (it is
  rendered, but the recipe needs a DOWN move that the pre-`07884d7` live-pad defect defeated).
- **Session and power** (`067d6f0`): Auto-Off darkens the display instead of quitting (broadcast
  `SC_MONITORPOWER`, read back `GUID_CONSOLE_DISPLAY_STATE`, reversible), `--kiosk` / `--display` /
  `--start-windowed` with verified frameless fullscreen on a chosen display, real DualSense/DS4 battery
  and transport parsing in `pad.*` (hardware-verified 100% over USB), and `pause=` / F10 script tokens.
- **Services**: Steam library/collections/store/downloads/accounts/friends (`b339422` adds the two-step
  account-switch prompt with a dry run, `+app_stop` with a registry read-back, a friends avatar cache
  and the trophy verdict), native Jellyfin browsing and playback with DPAPI remembered sign-in and
  playback reporting (`3e5bcdf`), local photos, music and video with sidecar subtitles, resume points
  and the Video column's Continue Watching row, and the versioned imported-apps registry and editor.
- **Audio**: nine system cues decoded with a seventh Trophy slot, the firmware's single cue gain measured

- **Settings and state**: versioned `preferences.json` (document version 2, per-profile values and a

## 3. Build, run, verify

Unchanged from [HANDOFF-2026-10-27.md](HANDOFF-2026-10-27.md) sections 3 and 11; that file is still the
one-page operational reference. The short form, from the repository root:

```powershell
# Build. Stop re-ps3-native.exe first: the linker fails with LNK1104 while it runs.
& .\native-xmb\build.ps1
# -> out\native-xmb\re-ps3-native.exe plus the deployed Qt runtime

# Run. --dev-flash is required; without it the app prints usage and exits with code 2.
& .\run-native-xmb.ps1 -FlashRoot C:\path\to\dev_flash
```

Verification is the maintained product harness plus, for the fidelity track, the new parity tool:

```powershell
# Product gate: stored pair + canonical capture + named states.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\ab-layers.ts --all

# Fidelity corpus: catalogue, capture, score, references that are owed.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --catalogue
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --capture --score
& "$env:USERPROFILE\.bun\bin\bun.exe" work\parity.ts --references-missing
```

`work/release-check.ps1` wraps the release checks: it runs the layer gate as a **gate** (a non-zero
`ab-layers.ts --all` exit fails the run), `parity.ts --references-missing` as a **report** (it exits 1
while cells are missing; that number is published, never gated), and the credential, firmware-data,
dump, documentation-link and stale-commit scans. `-SkipBuild` is report mode (skips the two checks that
need a local build) and `-WhatIf` prints the plan without running anything. It does not yet run
`parity.ts --regression`; wiring that is Phase 16.3. Section 8 is the three-command shipping sequence.

## 8. How to ship

Three commands, in this order, from the repository root. All three are local: none pushes, tags,
uploads or deletes anything.

```powershell
# 1. Build. Stop re-ps3-native.exe first: the linker fails with LNK1104 while it runs.
& .\native-xmb\build.ps1
# -> out\native-xmb\re-ps3-native.exe, the deployed Qt runtime, re-ps3-native.pdb

# 2. Gate. Product harness: stored pair + canonical capture + every named state.
#    Exits non-zero on a layer or named-state failure. This is the number a release quotes.
& "$env:USERPROFILE\.bun\bin\bun.exe" work\ab-layers.ts --all

# 3. Release check. Runs the same gate (as a gate) plus the credential, firmware-data, dump,
#    documentation-link and stale-commit scans. Exits non-zero on any of them.
```

## 9. Release and tag checklist

**No tag exists today** (`git tag` is empty) and **this pass did not create one**: tagging is the
parent's decision. What follows is the exact procedure so the release is mechanical when it is approved.

### 9.1 Version string

- One version, two places, and they must agree:
  - `project(RePS3Native VERSION 0.2.0)` in `native-xmb/CMakeLists.txt`
  - `app.setApplicationVersion("0.2.0")` in `src/main.cpp`
- Today's version is **0.2.0**. `--version` prints `re-ps3-native 0.2.0`.
- The tag is `native-xmb-v<version>`, so today that would be **`native-xmb-v0.2.0`**.
- [PHASES-2026-10-28.md](PHASES-2026-10-28.md) 8.5 expects the release after the Phase 8 repair to be
  **`native-xmb-v0.2.1`**. A bump is a source edit to the two lines above (a two-file commit of its own,
  before the tag), not a tag-time decision.

### 9.2 Tag command and annotation format

Annotated tag on the release commit, never a lightweight tag:

```powershell
git tag -a native-xmb-v0.2.0 -F .\release-notes.txt <release-commit>
git show native-xmb-v0.2.0 --stat        # read it back before anyone pushes
git push origin native-xmb-v0.2.0        # only with explicit approval
```

`release-notes.txt` is ASCII and follows this shape - measured numbers, each with the command that
produced it, and no claim the gate cannot support:

```text
native-xmb v0.2.0

commit <40-hex release commit>
built with Qt 6.12.0 / MSVC 14.4x on Windows x64

gate    bun work/ab-layers.ts --all -> exit 0; 6/6 layers, 12/12 named states
check   work/release-check.ps1 -> RESULT PASS (6 passed, 0 failed, 1 report-only)
isa     31/66 criteria checked (ISA.md)
fidelity parity.ts --references-missing -> 16 cells without a matched reference (report only)
notes   <one paragraph: what changed since the previous tag; for the first tag, since a445f4a>
limits  <the two or three limits a user will hit first, taken from section 2, not paraphrased>
```

### 9.3 Commit message format

The repository's own style, unchanged: one subject line naming the phase or area and the change, then
optional body paragraphs with the measured numbers and the documents that carry them. No trailers, no
generated text, no emoji, no ALL-CAPS.

```text
Phase 8.5 packaging: INSTALL refreshed against the CLI, release-check extended, handoff ship list

<what changed, in the order a reader needs it; every metric with the command that produced it;
 the documents and audits that hold the evidence; what was NOT run>
```

A commit that quotes a status names the commit it was read at. A commit that changes a threshold, a
budget or a reference says so in the subject, because that is the change a reviewer must not skim.

### 9.4 What a release must not include

- **No tag on a red or skipped gate.** A tag is created only after a full `release-check.ps1` run with
  `gate PASS` on the tagged commit, and `ab-layers.ts --all` exiting 0.
- **No firmware assets or derived data** in any commit: no `dev_flash` tree, decrypted `*.prx`,
  `.rco`/`.prf`/`.gim`/`.p3t`/`.raf` containers, RCO/PRF dumps, shader dumps or contact sheets.
- **No Steam key, Jellyfin token, password, JWT, NPSSO or PSN id** in the tree, the notes, the commit
  messages or the tag annotation.
- **No captured frames, reference frames, named-state seed data or scorecards** in git; they are local,
  gitignored evidence (`out/`), and the release notes cite them instead of carrying them.
- **No build outputs** (`out/`, `*.exe`, `*.obj`, `*.pdb`) in the tree. The portable folder is a copy
  of the output folder, not a commit.
- **No version bump without the gate re-run.** If `CMakeLists.txt`/`main.cpp` change the version, the
  build and gate must be re-run before the tag, because the tagged binary is the one users get.

## 10. What is deliberately not shipped

The line between "not done yet" and "will not ship" matters more than either list. These are decisions,
not backlog items; the forward plan's own do-not-build table is
[PHASES-2026-10-28.md](PHASES-2026-10-28.md) section 4.

| Not shipped | Why | Where it is enforced |
|---|---|---|
| **The firmware** (`dev_flash`, encrypted `*.sprx`, decrypted `*.prx`, `*.rco`, `*.prf`, `*.gim`, `*.p3t`, `*.raf`, `*.qrc`) | Sony's assets, not this project's. The app reads a local copy that the user supplies and never writes to it. | `.gitignore`; `release-check.ps1` `data` check (tracked, untracked and embedded base64). |
| **Anything decoded from the firmware** - RCO/PRF object dumps, image exports, month sheets, icon sheets, shader dumps, texture contact sheets, theme `.p3t` extractions | Same reason as the firmware: the output is a copy of it. The analysis flags (`--rco-tree`, `--rco-images`, `--rco-text`, `--export-image`, `--p3t-dump`, `--dump-cg`, `--month-sheet`, `--icon-sheet`, `--decode-fp`) write outside the tree. | `.gitignore`; `release-check.ps1` `data` and `dump` checks. |
| **The Steam Web API key** | A personal credential. It lives in `STEAM_WEB_API_KEY` or `%APPDATA%\re-ps3-native\steam_api_key`, never in preferences, reports, manifests, logs or docs. | `.gitignore` (`steam_api_key*`, `.env*`); `release-check.ps1` `keys` check, including the exact value of the local key file. |
| **Jellyfin credentials** - password, access token, remembered session | The password is never stored. The token is memory-only unless the user opts into Remember, and then it is DPAPI-sealed for that Windows user in `<data>\jellyfin\session.bin`, outside the repository. | Code (`jellyfin_client.cpp`); `release-check.ps1` `keys` check for bearer/Emby tokens and JWTs. |
| **Console identity** (`IDPS`/`PSID`, console-local account files) | Emulated-console identity has no place in a PC reconstruction. | `.gitignore` (`console-psid*`, `idps*`); `release-check.ps1` `keys` file-name check. |
| **Captured frames and the reference corpus** - the RPCS3 root frame, named-state references, `out/native-reference/store/ui3-data` seeds, `out/parity/` runs, scorecards | Firmware-derived evidence that the gate needs locally and git must not carry. A clean clone cannot reproduce the gate for exactly this reason. | `out/` is gitignored; `release-check.ps1` `data` check. |
| **Build outputs** - `out/`, `*.exe`, `*.obj`, `*.pdb`, `*.ilk` | Reproducible from the commit; the portable folder is a copy of the output, not a versioned artifact. | `.gitignore`. |
| **An installer** | The `windeployqt` output folder is the release shape. Phase 7.1 stays "partly" because no clean-VM run of [INSTALL.md](INSTALL.md) has been recorded. | [PHASES-2026-10-28.md](PHASES-2026-10-28.md) 1.1 row 7.1. |
| **A `--diagnose` bundle** | Never implemented: `src/main.cpp` has no such option. The design (contents, redaction, 5 MiB cap) is [audit/DIAGNOSE.md](audit/DIAGNOSE.md). The crash stack in `XMB_LOG`/`crash.log` is the only diagnostic artifact that exists. | Code has no flag; [INSTALL.md](INSTALL.md) section 6 says so. |
| **Telemetry, uploads, auto-update, network calls in the release check** | Nothing is sent anywhere, ever, by the app or by `work/release-check.ps1`. A diagnostic bundle would have to be attached by hand. | Code; `release-check.ps1` header and behaviour (no network, no deletion). |
