# Breadth gate investigation (2026-11-11)

The reported 11/22 result is not eleven input-dispatch regressions. The original gate log
(`C:/dev/out/gate-full2.log`) already distinguishes failed assertions from failed pixel metrics.
The wanted video matrix, save-data pages and settings subpages are retained.

## Causes

* Music: `work/v2-fixtures.ts:102-108` generates the external WAV/cover and writes an
  absolute `library/music` path into the seed. Both `C:/dev/out/v2/music/Gate Tone.wav` and
  `folder.png` were absent. Navigation reached the Music Library, but its empty page had
  no playable row. This is not an Enter intercepted by the video matrix: that handler is
  guarded by both `videoPanelOpen_` and `shell_.videoOpen()` (`src/view.cpp:4826`).
* Stub launch: `work/v2-fixtures.ts:113-127` registers and builds
  `C:/dev/out/v2/stubgame.exe`. That executable was absent. The registered catalogue row
  still existed; `src/shell.cpp:2308-2312` correctly refused the missing executable before
  game boot. There was no runnable title to capture for in-game XMB.
  The save-data change only binds the four utility rows and appends `Action::SaveData`;
  it neither renumbers the existing enum members nor changes the imported-game route.
* Gallery: the read-only prerequisite `C:/dev/out/gal/photos` was absent. It is explicitly
  not generated by `work/v2-fixtures.ts:14-15,22,109`. An empty/missing library cannot emit
  the expected 374-photo / 17-folder / 49-pile index logs. Do not generate substitute
  photos or bless an empty-gallery reference.
* Auto-off: its state assertions pass (idle age 70000, display-off not requested). The
  pixel mismatch is the wanted firmware-backed PSP utility title, not the timer or guide:
  `src/save_data.cpp:14,20-22` resolves `msg_savedata_utility_minis_psp`, replacing
  `Saved Data Utility (PSP)` with `Saved Data Utility (minis/PSP™)` on the root behind
  the unchanged guide. The old reference still had the literal short title.
* Subtitle: media opens, pauses, seeks to zero and loads the sidecar; the cue band matches
  exactly. The full-frame mismatch is the intentional `00:00` to `00:00:00` time-cell
  formatting in `src/view.cpp:3695-3706` from the video-control breadth change.

## Remediation

Restore the deterministic generated music/game fixtures with `bun work/v2-fixtures.ts`.
The script now also provides a read-only `--check` mode and reports missing external
prerequisites rather than claiming the complete environment is ready. The original gallery
library must be restored separately. Pixel references may only be refreshed for the verified
intentional video time format and firmware-backed PSP title, never for missing fixture data.

The first restoration attempt found a genuine fixture-tool defect: passing the quoted
`call "...Program Files.../vcvars64.bat"` command directly as a Bun spawn argument produced
backslash-escaped quotes that `cmd.exe` interpreted literally. The script now writes the
command to `C:/dev/out/v2/build-stub.cmd` and invokes that file by its unquoted basename;
the real MSVC stub build succeeds. Generation returns failure while the gallery prerequisite
is still absent, even though music and game fixtures have been restored.

Pixel inspection of the original failing captures confirms subtitle differs in only 980
pixels, all in y=963..983 (the time cells); auto-off differs in only 2668 pixels at
x=989..1183, y=985..1017 (the PSP title). Their cue band and timer behavior are unchanged.
The restored music-player-page passes all regions with infinite PSNR / SSIM 1.0000 without
changing application code or its reference.
