# PS3 firmware fetch research

Sony's regional list is `https://dus01.ps3.update.playstation.net/update/ps3/list/<region>/ps3-updatelist.txt`, for example [us](https://dus01.ps3.update.playstation.net/update/ps3/list/us/ps3-updatelist.txt), [eu](https://dus01.ps3.update.playstation.net/update/ps3/list/eu/ps3-updatelist.txt), and [jp](https://dus01.ps3.update.playstation.net/update/ps3/list/jp/ps3-updatelist.txt). The US list observed on 2026-11-10 has semicolon-separated `Dest`, `ImageVersion`, `SystemSoftwareVersion=4.9300`, `CDN`, and `CDN_Timeout` fields. Separate rows describe an incremental `PS3PATCH.PUP` and the full `PS3UPDAT.PUP`; select the latter. The CDN is currently an **absolute HTTP URL**, not a relative path, though a relative URL can be resolved against the list URL. The pattern is `/update/ps3/image/<region>/<dated-build-id>/PS3UPDAT.PUP`. Sony's endpoint serves plain HTTP only — its TLS certificate fails hostname validation (`SEC_E_WRONG_PRINCIPAL`), so HTTPS fails. The fetcher downloads over HTTP; authenticity is preserved because `extractPup` HMAC-SHA1-verifies every PUP entry with Sony's `PUP_KEY`, so a tampered PUP is rejected regardless of transport. [Sony's support page](https://www.playstation.com/en-us/support/hardware/ps3/system-software/) links the same HTTP PUP and specifies at least 200 MB free space (not an exact file size).

## Layout and extraction follow-up

The outer PUP has a header, entry table and hash table; entries are identified by IDs and carry offsets and lengths. See RPCS3 [`rpcs3/Loader/PUP.h`](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Loader/PUP.h) and [`PUP.cpp`](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Loader/PUP.cpp). It is not simply a sequence of encrypted files: RPCS3 validates the outer container and hashes, reads version entry `0x100`, then opens entry `0x300` as the `update_files` TAR. The TAR includes system packages such as CORE OS and `dev_flash_*`; the latter are signed/encrypted SCE packages, not plain outer PUP entries. RPCS3's [installer](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/rpcs3qt/main_window.cpp) filters `dev_flash_` names, runs `SCEDecrypter` with `SCEPKG_ERK` and `SCEPKG_RIV`, then extracts the third resulting stream as a TAR into dev_flash. Publicly known PS3 keys are present in RPCS3's source, for example [`Crypto/key_vault.cpp`](https://github.com/RPCS3/rpcs3/blob/master/rpcs3/Crypto/key_vault.cpp); AES decryption and decompression/unpacking are implemented in `firmware_extract.*` (see FIRMWARE-EXTRACT.md): `extractPup` HMAC-verifies every entry, decrypts each `dev_flash_*` SCE package, and unpacks the inner TARs into a `dev_flash` folder. The first-run setup's Firmware page exposes a "Download from Sony" row that chains `latestFirmware` → `downloadPup` → `extractPup` into `<data>/dev_flash`; the fetcher itself only locates the release.

The local RPCS3 source places the public keys in `rpcs3/Crypto/key_vault.h`. `PUP.h:9-32` defines a 48-byte header (8-byte magic followed by five big-endian 64-bit fields), followed by `file_count` 32-byte file entries and the same number of 32-byte hash entries. `PUP.cpp:82-111` verifies an HMAC-SHA1 over each entire entry using `PUP_KEY`, not a plain SHA-1. The package decryption is separate: `Crypto/unself.cpp:626-705` decrypts SCE metadata with AES-256-CBC and AES-128-CTR; `:710-817` decrypts sections with AES-128-CTR and decompresses compressed sections. The installer extracts the third resulting section of **each** package as its own TAR (`main_window.cpp:1670-1697`); concatenating all packages into a single TAR would not reproduce RPCS3. A safe implementation needs bounds checks, HMAC verification, secure TAR path handling and transactional output before exposing an extraction command.

## Version and distribution

This build targets **4.93**. The US list inspected on 2026-11-10 advertised `4.9300` (4.93), consistent with Sony's support page. The endpoint is HTTP-only (its TLS certificate fails hostname validation, `SEC_E_WRONG_PRINCIPAL`); the app downloads over HTTP and relies on `extractPup`'s per-entry HMAC-SHA1 verification for authenticity rather than TLS. Before installing, compare the normalized list version and the actual validated PUP's `0x100` version against 4.93, and reject or explicitly warn on mismatch; a list alone cannot verify downloaded content. The headless check only compares the advertised version.

RPCS3 supports installing Sony's official firmware supplied by the user; this feature likewise fetches Sony's own file for the user's machine. This is not legal advice: users should consider applicable law and Sony's terms. No firmware, keys, or secrets are committed to this public repository.
